1. Getting started

  1. Launch: double-click the desktop autoX icon. If it is already running, this opens the same local app.
  2. Sign in to X: Settings → Connect X account → authorize on X. Enter your password on X's own website. Your profile should appear when you return.
  3. Load data: start an X sync from Overview. This makes X API requests and requires appropriate permissions and available API allowance.
  4. Read the status: “Connected” indicates that an access token is present. A successful sync is a separate requirement; the app also shows sync errors.
  5. AI is optional: enter and save your OpenAI API key in Settings if you want AI features. Other local features do not require an OpenAI key.
Manual sync only. Each user supplies their own API credentials. Opening this app uses saved local data. Sync requires explicit confirmation and may make many paid API requests. Follower change tracking begins after the first complete snapshot.

2. One-time X sign-in setup

Once signed in, you do not need to enter these settings every time you launch the app.

  1. Open your application in the X Developer Console and enable OAuth 2.0 user authentication.
  2. The exact callback / redirect URL is http://127.0.0.1:4317/oauth/callback.
  3. In autoX Settings, enter your OAuth 2.0 Client ID in OAuth Client ID. If your application also has a Client Secret, enter that too.
  4. Save the connection settings, then select Connect X account.

A Consumer Key or app-level Bearer Token does not replace this sign-in. The user Access Token field is an advanced alternative; leave it empty for normal use. Secret fields remain empty after saving: the app does not send stored keys back to the browser. Saving an empty field keeps the previous key.

The app manages one X account's workspace. Do not connect another account to the same data directory. Requested permissions: tweet.read tweet.write users.read follows.read follows.write media.write offline.access. X determines actual endpoint access.

Understanding the follower log

The first successful complete fetch establishes a baseline. It cannot reconstruct earlier unfollows. A previous follower's disappearance must be confirmed by two consecutive complete fetches at different times. The event timestamp records when the change was detected. An incomplete or failed fetch does not prove an unfollow.

Understanding analytics

The app groups current post metrics available through the API by each post's UTC publication date. The chart does not show the day on which views occurred. Rankings cover the loaded posts and selected period; a complete account history is not guaranteed.

4. Posts, replies, images and scheduling

  1. In Outbox, choose a type and write your text. Replies require the target post's numeric ID: the number after /status/ in its X link. Replies started from Inbox or Engage fill this in for you.
  2. Save as a draft first. Saving a draft does not publish a post to X.
  3. Attach images through a separate upload: up to 4 PNG/JPEG/WebP files, each up to 5 MB. Uploading is already a live X action and requires separate confirmation. An older upload's media ID may expire; upload the image again if this causes an error.
  4. Before sending manually, check the text and target, then approve the send.
  5. For scheduling, choose a future time in your computer's local time zone and approve it. Keep the computer and autoX's background process running; a sleeping computer cannot send.

When paused, live sending, follow/unfollow actions and image uploads are blocked. Resuming may also start previously approved scheduled sends that are due, so review the queue first. Manual read-only sync remains available while paused.

If a scheduled send is more than 15 minutes late, the app returns it to draft for review. For an “Uncertain” status, first check X to see whether the post appeared; the app does not automatically retry. “Mark as sent” only changes local status and does not send anything.

You send DMs on X's website. autoX does not read your private messages. AI-generated text is also kept as a draft for review; it is not published automatically.

5. Settings and costs

  • Language: choose Magyar or English under Settings → Language. The interface changes immediately and remembers your choice after a reload.
  • Manual X sync only: there is no automatic data refresh. Sync asks for separate cost confirmation. A full sync may make dozens of paginated API requests. Reloading the app and the top Refresh button only read saved local data.
  • Daily API write limit: defaults to 20 write attempts per UTC day. Posts, replies, image uploads and follow/unfollow actions count; failed attempts may also consume the allowance. This is not a financial spending cap and does not limit reads.
  • Reach goal: a displayed target only, not an instruction to post automatically.
  • OpenAI: requires your own API key and an accessible model. The default model is gpt-4.1-mini. A ChatGPT subscription alone does not replace an API key or API allowance.
  • Automation: controls only approved scheduled sends. No autonomous AI reply bot or automatic follow/unfollow is enabled.

7. Backup, privacy and shutdown

Data folder: %LOCALAPPDATA%\Xauto. workspace.sqlite stores the workspace; credentials.dpapi is the encrypted key store tied to your Windows user. Logs: server.log and server-error.log. Keep secret keys out of screenshots, chats and public shares.

For backup, use Export & MCP → JSON export. CSV exports post data. Exports do not contain connection keys. Automatic JSON import is not available in the beta. For a full file backup, stop the app and copy the entire data folder; the encrypted key store may not be readable by another Windows user.

Closing the browser does not stop the server. Pause stops subsequent automatic actions; a request already started cannot be recalled. Shutting down the computer stops the app. In Task Manager, stop only the Node process belonging to autoX, not other Node apps.

Local data stays on your computer. X sync, sending and search communicate with the X API; AI requests send the selected context to the OpenAI API. The app listens only on the local address 127.0.0.1.

Read-only MCP server: node <autoX-folder>\mcp.mjs. Tools: read_summary, list_posts, list_followers, list_inbox, list_drafts. These read saved data only.

8. What did verification establish?

Local tests cover data storage, follower changes, analytics, HTTP protections, token handling, queue states, scheduling and several interface errors. The live X profile request and full data sync succeeded. Verification did not publish posts or replies, perform follow/unfollow actions, upload images or make paid AI requests.

This is a beta for personal use. Full feature parity with the reference SaaS, a complete historical follower log, daily post metric history, an Activity stream and an autonomous AI reply bot have not been verified. Error checks improve reliability but do not guarantee error-free operation in every possible situation.
